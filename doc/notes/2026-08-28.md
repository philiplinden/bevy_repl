# 2026-08-28 - Native Crossterm Migration & Architecture Deepening

## Overview & Context

Today we executed a major architectural overhaul of `bevy_repl` to remove `bevy_ratatui` and `ratatui` in favor of a native, in-schedule `crossterm` execution loop targeting Bevy 0.19.

This transition eliminates upstream git fork lock-in, unblocks publishing `bevy_repl` to `crates.io`, removes dozens of transitive dependencies, improves build times to sub-second incremental builds, and deepens the core domain modules.

---

## Key Architecture & Domain Model Changes

### 1. Unified `Repl` Resource (Single Source of Truth)
- **Eliminated**: `ReplTerminal`, `ReplPrompt`, and `ReplPromptConfig`.
- **Consolidated**: The single `Repl` resource now owns:
  - Session state (`buffer`, `cursor_pos`, `prompt_symbol`, `toggle_key`)
  - Command registry (`commands: HashMap<String, Box<dyn CommandParser>>`)
  - Terminal device helpers (`init_terminal`, `restore_terminal`, `clear_terminal`)
- **Default State**: Starts `enabled: true` by default, armed with raw mode and DECSTBM scroll region at startup.
- **Benefit**: No deferred `commands.insert_resource::<ReplTerminal>()` or `commands.remove_resource` during runtime enable/disable transitions. `repl.enabled` is the single source of truth.

### 2. Streamlined Terminal Output & Scroll Engine (`src/print.rs`)
- **Eliminated**: Static global atomics (`SCROLL_H`, `SCROLL_RESERVED`).
- **DECSTBM Scroll Region**: Uses `\x1B[1;{H-1}r` to partition rows $1 \dots H-1$ for log scrolling, while keeping the prompt pinned on row $H$.
- **Dynamic Adaptivity**: Queries `crossterm::terminal::size()` on each write so terminal resizing never desynchronizes cursor positions.
- **Safe Multi-Line Printing**: Splits strings by `.lines()` and guarantees column 0 alignment and explicit `\r\n` newline handling via `repl_println!` / `repl_print`, preventing raw-mode diagonal stair-stepping.

### 3. Direct Crossterm Input & Keymap Ingestion (`src/input.rs` & `src/keymap.rs`)
- **Direct Event Ingestion**: Ingests `crossterm::event::KeyEvent` directly via non-blocking `poll(Duration::ZERO)` in `ReplSet::Capture` (filtering for `Press | Repeat` across platforms).
- **Synchronous Mutations**: Keystrokes mutate `Repl` synchronously within the frame rather than buffering through deferred inter-frame message queues.
- **Immediate Submission Observer**: Pressing `Enter` triggers `commands.trigger(ReplSubmitEvent(line))` immediately.
- **Exact Modifier Matching**: Fixed `Binding::matches` to strictly compare modifiers, ensuring `Enter` (`NONE`) triggers submission while `Shift + Enter` (`SHIFT`) inserts `\n`.
- **Raw-Mode Ctrl+C Safety**: Intercepts `Ctrl+C` in raw mode, restores terminal cooked mode immediately, and emits `AppExit::Success`.
- **Input Suppression**: `suppress_game_keyboard_input` clears `ButtonInput<KeyCode>` and `Events<KeyboardInput>` while `repl.enabled == true`.

### 4. Zero-Channel Direct Tracing Layer (`src/tracing.rs`)
- **Replaced `log_ecs.rs`**: Eliminated `std::sync::mpsc` channels and `MessageReader<LogEvent>` frame buffering.
- **Direct Streaming**: Uses `ReplMakeWriter` / `ReplWriter` to stream formatted `tracing` bytes line-by-line straight to `repl_print` at row $H-1$.
- **Automatic Fallback**: If `bevy::log::LogPlugin` is absent (headless/minimal apps), `ReplPlugin::build` automatically initializes the global subscriber.
- **Ergonomic Helper**: Provided `DefaultPlugins.adapt_for_repl()` for zero-boilerplate logging in windowed games.

### 5. Robust Command Trait & Derives (`src/command/`)
- **`ReplCommand::to_event`**: Required method mapping `clap::ArgMatches` $\to$ `Self` event struct, eliminating silent argument dropping and removing the artificial `Default` bound.
- **Dual Macro Design**: Supports `#[repl_command]` attribute macro (auto-injecting `clap::Parser`, `Event`, and `Clone`) alongside `#[derive(ReplCommand)]`.

### 6. Pruned Dependencies & Fast Local Build Setup
- **Removed**: `bevy_ratatui`, `ratatui`, `anyhow`, `color-eyre`.
- **Retained Core**: `crossterm`, `clap`, `shell-words`, `ctrlc`.
- **Fast Build Config**: Created `.cargo/config.toml` utilizing `clang` + `lld` linker with nightly `-Zthreads=0` and `-Zshare-generics=y`.

## The Runtime-Toggle Spiral (Postmortem: Why We Cut Bait)

After the migration above, a long stretch was spent chasing a single feature — **letting the REPL be enabled/disabled at runtime via a keybind (e.g. F3) while the app keeps running, including in headless apps with no window** — through several rounds of "fix," each of which quietly broke an assumption the previous fix depended on. Recording the full loop so we don't re-walk it next time without remembering why it's hard, and why we chose to stop.

### The chain of narrow fixes, each invalidating the last

1. **v1 — coupled model**: `Repl::disable()` called `disable_raw_mode()`. The "obvious" mental model: `repl.enabled == raw mode`, 1:1 coupled.
2. **Break #1 — headless has no window**: In headless apps, Bevy's `ButtonInput<KeyCode>` never receives terminal keystrokes at all — it's fed by the OS window, which doesn't exist in headless mode. The moment raw mode went off, there was no channel left to detect the toggle key. Pressing F3 just echoed a raw escape sequence (`^[[13~`) to the screen; the REPL could never wake back up.
3. **v2 — always-on raw mode ("Choice A")**: Decoupled raw mode (process-lifetime, armed once at `Startup`, only torn down on exit/panic) from `repl.enabled` (a purely visual/session flag). `capture_terminal_input` runs unconditionally every frame so the toggle key is always seen instantly, regardless of session state.
4. **Break #2 — duplicated geometry math**: Fixing the above required scroll-region/prompt-row logic to run correctly in both enabled and disabled states. That geometry math (which row is reserved, what row output should target) turned out to be computed independently in ~6 different call sites across `repl.rs` and `print.rs`, several of which didn't agree with each other (e.g. `repl_print` unconditionally assumed a reserved row even while disabled — an off-by-one bug that would've stayed invisible until someone actually toggled off and started logging).
5. **Break #3 — logging seam duplication**: Separately, routing Bevy's tracing logs through the REPL's writer had used `LogPlugin.custom_layer` (an *additive* seam) instead of `LogPlugin.fmt_layer` (the *substitutive* seam meant for exactly this), causing every log line to print twice. Fixed by disabling `LogPlugin` entirely at first (too heavy — silently discarded the user's `filter`/`level`/panic-hook config), then narrowed toward the correct `fmt_layer` swap — but this was never finished before the toggle question below reopened the whole frame.
6. **Break #4 — Ctrl+C silently stopped working while disabled**: The Ctrl+C handler in `capture_terminal_input` was gated behind `if !repl.enabled { continue; }`, so toggling the REPL off also silently disabled the only way to exit the app via keyboard (raw mode suppresses `SIGINT` generation, so the OS-level `ctrlc` handler never fires either as a fallback).
7. **The root reconsideration**: Stepping back, "raw mode must always be on" was surfaced as a hard requirement, but it was actually **a design decision made on the fly to satisfy one specific goal — instant (sub-frame, no-Enter-required) keybind detection — that was never actually validated as a requirement.** No one had confirmed whether a lighter-weight terminal mode (e.g. POSIX `cbreak`: canonical/line-buffering off, but echo and `SIGINT` left alone) could deliver the same single-keystroke detection without paying for full raw mode's side effects, nor whether a few milliseconds of latency on the toggle would even be noticeable or matter.
8. **Ergonomics objection**: Separately, typing a full command like `repl` + Enter into a plain, un-prompted stdin (logs still streaming past with no visual cue you're "typing" anything) was explicitly rejected as bad UX — any toggle mechanism needs to be a single keypress, not a typed line, which is itself part of why the raw-mode question matters.

### Why we cut bait here

At step 7, a research task was queued (primary-source investigation into crossterm's raw-mode termios/console-mode flags, whether `cbreak` is exposed or buildable underneath crossterm, and prior art from tools like `less`/`top`) — but before it ran, we recognized this had become an increasingly deep rabbit hole for a feature that isn't load-bearing for a first working version. **Decision: park runtime enable/disable toggling entirely as a nice-to-have future feature.** The REPL ships always-on for now (no F3, no disabled state, no dual-mode input handling). This removes essentially every item in the chain above from the current scope — the geometry-duplication and Ctrl+C-while-disabled bugs stop being live bugs the moment there's no "disabled" state to fall into; the logging-seam fix (`fmt_layer`) remains worth finishing on its own merits, independent of toggling.

### What this leaves genuinely open for a future session

- Whether POSIX `cbreak` (or an equivalent Windows console mode) can deliver single-keystroke hotkey detection without full raw mode's side effects (echo off, `SIGINT` suppressed) — unresearched, flagged, not yet investigated.
- Whether crossterm exposes this or it would need manual `termios`/console-mode calls underneath/alongside it.
- If/when toggling returns: the geometry-single-source-of-truth question (six duplicated row-math call sites) and the "Ctrl+C must always work regardless of session state" fix both need to land before re-enabling a disabled state, not after.
